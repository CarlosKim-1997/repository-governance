# Release procedure and gate

Distribution 0.2.0 remains development. Before a stable 1.0.0 release, freeze the Core and five schemas; verify exact template Core/guidance/helper copies; bundle the offline checker; pass generic checker, installer, replay, and read-only helper fixtures; prove Greenfield and Brownfield safety, partial-install detection and safe stop, idempotency, clean-room non-JavaScript installation, reference regression, and an unrelated non-web repository case. Scan reusable files for project-specific leakage. Generate a distribution manifest and SHA-256 checksums, verify them, and complete a read-only final audit.

`npm run release:manifest` writes ignored development metadata to `dist/development/` with `source_commit: DEVELOPMENT_WORKTREE`; it does not identify a committed source snapshot. After the source tree is committed and clean, `node tooling/release-manifest.mjs --release` may generate ignored output in `dist/release/` with that stable HEAD SHA. Generated output is not checked back into the source commit, avoiding a self-reference. Verify hashes, then package the versioned archive separately. Building locally does not authorize publication. The checker validates structure only; semantic adoption and release readiness require human review.
